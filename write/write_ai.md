Introduction
近年来，基于大语言模型的智能体（LLM agents）逐渐从封闭的文本生成系统走向能够自主调用工具、访问外部信息并执行多步任务的交互式系统。通过调用搜索引擎、邮件服务、数据库、支付接口和文件管理工具，智能体能够处理更加开放、复杂且贴近真实业务的用户请求。然而，工具使用能力的扩展也引入了新的安全风险：智能体在执行用户任务时，往往需要读取来自网页、邮件、文档、数据库或第三方 API 的外部内容，而这些内容并不一定可信。攻击者可以在不修改系统提示词、用户指令或模型参数的情况下，将恶意指令嵌入工具返回值中，并利用智能体对外部信息的依赖，诱导其执行与原始任务无关甚至具有破坏性的工具调用。这类攻击通常被称为间接提示注入（indirect prompt injection, IPI），已经成为工具调用型智能体面临的核心安全威胁之一。

与传统的提示注入不同，间接提示注入的关键困难在于，攻击者并不直接控制智能体的初始输入，而是通过智能体在任务执行过程中接触到的环境信息影响其后续决策。因此，攻击是否成功不仅取决于恶意文本是否被模型识别，还取决于该恶意信息能否被合理地嵌入正常业务流程，并最终改变智能体的工具调用行为。现实中的高质量攻击不应表现为一次突兀的指令跳转。例如，在一个正常的酒店预订任务中，工具返回值突然要求智能体向攻击者发送邮件，通常很容易被安全机制识别。更具挑战性的攻击会伪装成业务流程中的正常步骤，使智能体先继续执行若干合理操作，再在更晚的时间点转向一个用户从未授权的敏感操作。此类攻击在表面上可能与正常任务轨迹高度相似，但其恶意意图会在多轮交互之后才显现。我们将这种攻击称为潜伏式间接提示注入（latent indirect prompt injection）。

现有研究主要从两个方向缓解间接提示注入风险。一类方法依赖输入过滤、护栏模型或专门的注入分类器，在工具结果进入模型上下文前识别可疑内容；另一类方法通过监督微调、偏好优化或强化学习，使智能体学习拒绝潜在的恶意指令。这些方法在面对静态、显式的攻击模板时能够取得一定效果，但仍存在两个局限。首先，攻击者可以根据防御策略自适应地改变注入位置、表达方式和行为路径，仅依靠固定攻击样本训练得到的防御器很难覆盖持续变化的攻击分布。其次，许多防御策略将“拒绝可疑内容”作为主要安全目标，却没有充分区分安全性与任务效用。智能体虽然可能因此避免执行攻击，但也可能拒绝读取正常工具结果、提前终止任务、重复调用工具，或者直接放弃原本可以安全完成的用户请求。对于实际应用而言，一个只能通过停止服务来保证安全的智能体并不能满足用户需求。

攻击侧同样存在一个容易被忽视的问题：如果攻击器只以“攻击轨迹与正常轨迹不同”或“任务结果发生变化”为优化目标，那么它可能会找到一种更容易获得成功信号的捷径，即篡改正常任务内部的结果，而不是诱导智能体执行真正越权的恶意操作。例如，攻击器可以修改酒店价格、搜索结果或交易金额，使最终输出与干净执行结果不同，但智能体并没有调用任何用户未授权的敏感工具。在这种情况下，攻击成功率可能被高估，而攻击器实际上并未完成真正的权限越界。一个合理的自适应攻击目标应当独立于用户的正常任务，并明确指向良性计划之外的敏感工具或敏感操作。

基于上述观察，我们提出 EvoGuard，一个面向工具调用型大语言模型智能体的攻防协同进化框架。EvoGuard 的核心思想是让攻击策略和防御策略在多轮交互中相互适应：攻击器根据当前防御器搜索更隐蔽、更难检测的注入方式，防御器则利用当前攻击器产生的成功与失败轨迹更新自身策略。与只在固定攻击集合上训练防御器不同，EvoGuard 将智能体安全建模为一个持续变化的攻防过程，并将攻击成功、安全行为和用户任务完成度纳入同一个训练闭环。

为了刻画潜伏式攻击，EvoGuard 构造了同一任务下的干净轨迹与受攻击轨迹，并在注入发生之前重放干净轨迹中的动作，从而保证两条轨迹具有一致的前缀。随后，系统根据受攻击轨迹首次偏离干净任务计划的时间点，定义从攻击载荷暴露到行为转折之间的时间距离：

[ \Delta = t_{\text{turning}} - t_{\text{injection}}. ]

其中，(t_{\text{injection}}) 表示恶意内容进入工具观测的时间，(t_{\text{turning}}) 表示智能体首次执行可归因于攻击目标、且偏离干净计划的行为。较小的 (\Delta) 对应即时触发式攻击，而较大的 (\Delta) 则表示攻击载荷在上下文中潜伏了更长时间后才产生可观测的行为影响。相较于仅检测注入文本或寻找工具调用序列的首次差异，基于干净反事实轨迹的定义能够更直接地描述攻击从“信息暴露”到“行为偏移”的过程。EvoGuard 进一步使用该信号引导基于蒙特卡洛树搜索的攻击器，在注入时机、注入方式和攻击载荷之间进行联合搜索，并优先保留既能实现恶意目标、又具有较高行为延迟的攻击。

为了避免攻击目标退化为正常任务篡改，EvoGuard 为每个任务构造独立的恶意目标，并将目标绑定到良性计划之外的敏感工具或敏感操作。攻击器需要诱导智能体执行转账、数据外传、权限修改或破坏性操作等用户未授权行为，而不能仅仅改变正常任务的输出结果。与此同时，潜在的敏感工具会同时出现在干净轨迹和受攻击轨迹中，以避免智能体仅凭工具列表差异识别攻击。对于具有严格数据划分的数据集，攻击目标也仅从训练划分中采样，从而防止验证集和测试集中的工具信息泄漏到训练攻击载荷中。

在防御侧，EvoGuard 将安全性与任务进展显式分解为不同的训练信号。对于受攻击轨迹，安全信号用于判断当前动作是否执行了恶意操作；对于干净轨迹，系统则评估智能体是否继续推进原始用户任务。更重要的是，任务进展信号以干净轨迹作为参照，区分“安全且完成任务”和“安全但停止服务”两种行为。防御器不仅需要避免执行恶意工具调用，还需要在拒绝攻击之后回到原始任务流程，继续完成用户请求。EvoGuard 进一步通过格式稳定性惩罚减少模型在安全决策过程中产生的无效输出、重复调用和结构化工具调用错误。训练过程中，攻击成功轨迹中的行为偏离距离 (\Delta) 被用于调整策略梯度优势，从而逐步提高防御器对潜伏式攻击的关注，而不改变原始奖励的语义和尺度。

EvoGuard 采用监督微调与逐轮强化学习相结合的训练方式。初始监督阶段通过干净轨迹、已成功防御的攻击轨迹以及经过纠正的攻击轨迹建立基本安全边界；后续强化学习阶段则在当前攻击器生成的动态攻击分布上持续优化防御策略。每一轮训练完成后，更新后的防御器会成为下一轮攻击搜索的目标，攻击器也会据此产生新的攻击样本。这样的闭环使防御器不再只学习拒绝已知攻击模板，而是逐步面对由自身能力提升所诱导出的更隐蔽攻击。同时，独立的任务进展奖励能够抑制“通过拒绝所有外部信息来获得安全性”的退化行为。

我们在多个工具调用型智能体环境上评估 EvoGuard，并采用工具实际执行的验证集和测试集重放，而不是仅基于文本分类结果衡量防御效果。评测同时报告攻击成功率、攻击载荷送达率、干净任务完成率、良性行为保持率以及未完成任务比例，从而区分真正抵抗攻击与绕开受污染工具两种不同现象。实验结果表明，监督微调能够显著建立初始的攻击防御能力，而后续的效用感知强化学习主要改善防御过程中的过度阻塞和任务中断问题，使智能体在保持安全行为的同时恢复更多良性任务能力。进一步的攻防演化过程显示，随着即时触发式攻击逐渐被压制，攻击器会尝试转向具有更长行为延迟的潜伏式攻击，说明仅依赖静态注入样本评估防御能力可能会低估自适应攻击的真实难度。

综上，本文的主要贡献包括：第一，提出一种基于干净反事实轨迹和行为转折延迟 (\Delta) 的潜伏式间接提示注入刻画方法，并将其用于攻击搜索与防御训练；第二，提出独立于用户正常任务的敏感目标构造机制，避免攻击器通过篡改正常任务结果获得虚假的攻击成功；第三，提出将安全性、任务进展和输出稳定性显式解耦的防御训练目标，使智能体能够在拒绝恶意操作后继续完成用户任务；第四，建立面向自适应间接提示注入的多轮攻防协同进化流程，并通过工具执行型的留出重放评测同时衡量攻击抵抗能力与良性任务效用。
